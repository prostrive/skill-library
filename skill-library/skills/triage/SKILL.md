# Triage

Turn a batch of tickets into tickets that an agent or a dev can build. The dev makes the calls. This skill reads, checks and writes.

## Tracker

Read `docs/agents/tracker.md` for the tracker, the team, the statuses and the labels. When the file is missing, use the Linear MCP and the team's existing statuses. Do not invent statuses or labels.

## 1. Collect the batch

Get the tickets the dev names: a list of IDs, a status, a label, a cycle or a person. Follow pagination to the end.

## 2. Read every ticket in full

For each ticket, read the description, the comments, the attachments and the linked tickets. Read earlier triage notes, so you do not ask again what is already answered.

Report coverage as a line: `Read 23 of 23 tickets.` If a ticket could not be read, name it and say why. Do not continue with a partial batch without saying so.

## 3. Check each ticket against the code

- **Already built?** Search the code for the behavior by its domain meaning, not only by the ticket's words. Say where you looked.
- **Duplicate?** Search the tracker for a ticket that covers the same capability.
- **Claim holds?** For a bug, try to reproduce it from the steps in the ticket. Report one of: confirmed (with the code path), not reproduced, or not enough detail.

## 4. Group

Group the tickets by cause or by area, for example "these 8 come from one filter bug". Show the groups with one line per ticket: ID, title, what you found in step 3.

## 5. Ask the dev

List what is unclear per ticket. Ask at most 3 questions at a time. Recommend an answer for each question. Do not ask what the code or the tracker can answer.

The dev decides:

- the approach per group,
- what is out of scope,
- which tickets close as duplicate, already built or won't fix,
- which tickets need a person and which an agent can take.

Do not write a brief for a ticket with an open question. When the reporter must answer, write triage notes on the ticket instead (format below) and move it to the tracker's "needs info" status.

## 6. Write the briefs

For each ticket the dev cleared, write an agent brief as a comment on the ticket. Use [references/agent-brief.md](references/agent-brief.md). Build the brief from the dev's answers, not from your own guesses. Then move the ticket to the tracker's "ready" status.

Begin every comment you post with `Generated by AI during triage.`

## Triage notes format

```markdown
Generated by AI during triage.

**Known so far:**
- point 1

**Still needed from the reporter:**
- one specific question
```

## Finish

End with one table: ticket, group, outcome (brief written, needs info, duplicate, already built, won't fix), and what still needs the dev.

## Quick moves

When the dev says "move X to ready", do it. Say what you will change (status, comment, close) before you change it. Ask whether they want a brief first.
