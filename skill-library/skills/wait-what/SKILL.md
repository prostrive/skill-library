# Wait, what?

The dev did not understand your last message. Say it again so it lands. Shorter is not the goal.

1. Start with one or two sentences of context: what you were working on and why this message matters now.
2. Then say the point of the message: what you found, what you did, or what you need from the dev.
3. Use plain words and short sentences, like one person talking to another. One idea per sentence.
4. Use the words from `GLOSSARY.md` when the repo has one. If `GLOSSARY-MAP.md` exists, follow it to the right glossary. Do not use internal labels you made up in this session.
5. Explain a technical term the first time you use it, or replace it with plain words.
6. If the message asked the dev something, end with that question, asked plainly.

Do not apologize. Do not repeat the old message with small edits.
